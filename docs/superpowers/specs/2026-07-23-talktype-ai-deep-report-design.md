# TalkType AI 深度报告设计

## 背景

当前 TalkType 结果页已经能展示人格身份、沟通代码、成熟度、SWBC 四维分数、优势、盲区、训练方向和分享能力。问题是报告的信息密度还偏“测评结果摘要”，用户看完能知道自己是哪类人，但未必会产生强烈的“这说的就是我”的共情感。

本次增强采用“规则基础报告 + AI 深度解读”的混合方案：

- 规则基础报告负责稳定、可信、可解释。
- AI 深度解读负责生活化、共情感、个性化表达和转化引导。
- 免费内容必须足够完整，用户愿意截图、转发、讨论。
- 深度 AI 内容可以成为登录、订阅或后续付费闭环的承接点。

## 目标

1. 让结果页从“分数页”升级为“人格报告页”。
2. 让用户读到具体、熟悉、有画面感的描述。
3. 保留现有分享卡能力，同时提升报告页本身的停留和分享意愿。
4. 为后续订阅闭环预留“AI 深度报告”解锁位置。
5. 不破坏现有 TalkType 测评算法和 SEO 页面结构。

## 非目标

1. 不在本阶段重做题库评分算法。
2. 不新增真实心理诊断、医学或心理咨询承诺。
3. 不把完整结果隐藏到付费后；基础结果仍应开放。
4. 不上线未完成的“高情商评分器”和“情商急诊室”入口。

## 推荐方案

第一版采用 A + B：

### A. 杂志式基础报告

基础报告完全基于现有规则数据生成，免费展示，强调可读性和分享感。

结果页新增以下内容块：

1. **一句话读懂你**
   - 用人格类型、最高维度、最低维度生成一段生活化总结。
   - 例如：你不是单纯“会说话”，而是会记住关系里的细节，并愿意用一次次稳定回应把关系养起来。

2. **别人眼中的你**
   - 用 3 个短标签 + 1 段解释表达外部印象。
   - 来源优先使用人格优势、关系行为、职场行为。

3. **你容易忽略的事**
   - 从盲区和最低维度生成提醒。
   - 语气避免批判，采用“你不是不懂，只是容易……”的表达。

4. **三种关系里的你**
   - 展示亲密关系、职场沟通、朋友相处三张小卡。
   - 直接复用 `relationshipBehavior`、`workplaceBehavior`、`friendshipBehavior`。

5. **你的沟通成长路径**
   - 继续展示训练方向，但改造成更像行动建议。
   - 每条建议拆成“为什么需要练 + 可以怎么练”。

### B. AI 深度画像报告

AI 深度报告在基础报告之后出现，做成“预览 + 解锁完整”的结构。

免费预览展示：

1. **AI 读到的隐藏模式**
   - 一段 80-120 字解读。
   - 聚焦用户为什么会这样回复，而不只是“你是什么人格”。

2. **最容易戳中你的三句话**
   - 生成 3 个高频触发语句。
   - 例如：“你想太多了”“随便你吧”“我最近太忙了”。

3. **一句专属提醒**
   - 给用户一个能截图传播的句子。

完整报告预留模块：

1. 你在关系里的真实需求。
2. 你最容易被误解的地方。
3. 你在亲密关系、职场、朋友场景里的典型反应。
4. 适合你的沟通练习。
5. 3 条可直接套用的高情商回复模板。

第一版可以先不接支付，只保留“生成完整 AI 深度报告”的状态位和 UI 区域；如果项目已有订阅能力，则后续接入支付权益判断。

## 数据设计

### 新增基础报告 helper

建议新增 `talktypeReport.ts`，输入 `TalkTypeResult`，输出稳定报告数据：

- `identityInsight`
- `externalImpressionTags`
- `externalImpressionText`
- `blindSpotInsight`
- `relationshipSections`
- `growthPlan`
- `aiPreviewSeed`

这部分不依赖后端，适合写单元测试。

### AI 报告输入

AI prompt 不直接让模型决定人格类型，而是传入已计算好的结构化结果：

- 人格名称和英文代号。
- SWBC 四维分数。
- 成熟度分数。
- 优势、盲区、训练方向。
- 三类关系行为。
- 用户 24 道题的选择摘要。

模型只负责生成“表达层”和“个性化解释层”。

### AI 报告输出

后端或前端服务层应要求模型返回 JSON：

```json
{
  "hiddenPattern": "string",
  "innerNeed": "string",
  "triggerPhrases": ["string", "string", "string"],
  "misreadByOthers": "string",
  "relationshipNotes": {
    "relationship": "string",
    "workplace": "string",
    "friendship": "string"
  },
  "growthSuggestion": "string",
  "practicePrompts": ["string", "string", "string"]
}
```

前端只渲染字段，不直接渲染自由格式 Markdown，避免样式不可控。

## Prompt 原则

1. 不允许使用诊断式语言。
2. 不允许绝对化判断，如“你一定”“你永远”。
3. 多使用“你可能”“你常常”“在某些关系里”。
4. 文案要具体、有画面感，不要玄学化。
5. 每段控制在 80-140 字，移动端易读。
6. 结果要承认优势，也指出温和盲区。
7. 输出必须符合 JSON schema，失败时使用本地兜底文案。

## 页面结构

结果页推荐顺序：

1. 顶部身份卡：保留人格插画、人格名、沟通代码、分享短句。
2. 快速画像：一句话读懂你、别人眼中的你、你容易忽略的事。
3. SWBC 四维图：保留现有进度条，文案改得更生活化。
4. 三种关系里的你：亲密关系、职场、朋友。
5. AI 深度解读预览：隐藏模式、触发语句、专属提醒。
6. 成长路径：训练方向和练习建议。
7. 分享与保存：保留现有分享文案、保存图片、二维码能力。

## 交互和状态

1. 完成测试后先展示规则基础报告。
2. AI 报告区域默认显示加载态或预览态。
3. 如果 AI 成功返回，替换成深度解读。
4. 如果 AI 失败，展示本地兜底内容，不影响基础结果页。
5. 如果后续接订阅，未订阅用户看到预览和解锁按钮；已订阅用户看到完整报告。

## SEO

结果页内容由用户答题后生成，不直接作为可索引静态内容。SEO 仍主要依赖 `/talktype` 公开页面已有的 FAQ、介绍和结构化数据。

本次可以补充 SEO 文案方向：

- “TalkType 不只给你 EQ 分数，还会生成沟通人格报告。”
- “完成测试后获得 SWBC 四维画像、优势盲区和 AI 深度解读。”

不要把 AI 生成的个人报告写入静态 SEO 内容，避免重复、不可控和隐私问题。

## 测试计划

1. `talktypeReport` helper 单元测试：
   - 能根据人格和分数生成基础报告字段。
   - 最低维度不同，盲区提醒不同。
   - 三类关系文案来自人格数据。

2. AI 报告解析测试：
   - 合法 JSON 能被解析。
   - 缺字段时能回退。
   - 空数组或过长文案能被处理。

3. 页面验证：
   - 移动端结果页不卡屏、不出现文字挤压。
   - 分享和保存图片能力不回退。
   - AI 失败时基础报告仍可读。

4. 构建验证：
   - `pnpm check`
   - `pnpm test:talktype`
   - `pnpm build`

## 实施顺序

1. 先做规则基础报告 helper 和测试。
2. 改造结果页 UI，把报告层级展示出来。
3. 增加 AI 深度报告 UI 的静态兜底数据。
4. 接入项目已有 AI 调用能力。
5. 加入加载、失败、重试和后续订阅解锁状态。

## 风险

1. AI 文案如果太泛，会降低可信度。
   - 解决：prompt 输入结构化测评结果，并限制输出字段。

2. 报告太长会影响移动端阅读。
   - 解决：采用卡片分段，每段 80-140 字。

3. AI 生成速度慢会影响结果页体验。
   - 解决：先展示规则报告，AI 内容异步补充。

4. 付费入口过早会影响分享传播。
   - 解决：免费报告完整展示，AI 深度报告只作为增强层。

## 通过标准

1. 用户完成测试后，结果页至少新增 4 个可读报告模块。
2. 用户不需要理解 SWBC，也能通过文字知道“自己像什么”。
3. AI 深度报告失败时，结果页仍完整可用。
4. 移动端结果页阅读顺畅，按钮和分享能力正常。
5. 所有新增报告文案都有数据来源或兜底逻辑。
